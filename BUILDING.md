# Сборка и запуск GratiaVR

Рабочий проект: `GratiaVR/GratiaVR.uproject`. Движок по умолчанию: UE 5.8.3 в `E:\ue\UE_5.8`.
Карта проекта и где что лежит — [README.md](README.md).

## Редактор

**Open-Editor.cmd** компилирует C++ (`GratiaVREditor`) и открывает проект. Play запускает игру
на мониторе, Play ▸ VR Preview — в шлеме (сначала SteamVR). Если редактор уже открыт, скрипт
ничего не делает: C++ нельзя пересобрать при открытом редакторе.

## Сборка игры

1. Закрыть игру и Unreal Editor, запустить **Build.cmd** в этой папке. Он вызывает единственный
   активный pipeline `GratiaVR/Scripts/Build-Stage1.ps1`: компиляция редактора, cook, упаковка,
   проверка отпечатка исходников и копирование в `Builds/Windows`.
2. Для VR сначала запустить SteamVR и подключить шлем с двумя контроллерами, затем **Start-VR.cmd**.
3. Для настольного запуска использовать **Start-Desktop.cmd**.

Единственная папка готового пакета: **Builds/Windows**. Каждый успешный Build.cmd обновляет её;
промежуточная копия `GratiaVR/Saved/StagedBuilds` удаляется после успешной сборки, а `GratiaVR/Saved/Cooked`
остаётся: следующая сборка готовит ассеты инкрементально (`-iterativecooking`) — заново только изменённые, шейдеры
из DDC. В пакет идёт только гостевой дом (сцена «Гостевой дом» и шоу «Позирование»): пак ночного квартала
(`/Game/SoulCity`) не готовится никогда (`DirectoriesToNeverCook`). Если игра запущена, сборка останавливается перед копированием и сообщает об этом;
прежний пакет остаётся целым. Перед запуском ярлыки проверяют SHA256 исполняемого файла и
показывают build id из `build_manifest.json`.

Команды из терминала:

```cmd
Build.cmd
Build.cmd -EngineRoot "D:\Unreal\UE_5.8"
Build.cmd -RegenerateScenes
Start-VR.cmd
Start-Desktop.cmd
```

`-RegenerateScenes` перед сборкой запускает подготовку сцен:

1. `setup_fab_environments.py` — уровни сцен из паков Fab (маркеры, колонки, свет под музыку);
2. запекание Lightmass для карт, которые на этой машине ещё не запекались (отметки в
   `GratiaVR/Saved/FabBake`; первый раз — около 10–20 минут);
3. `setup_scene_experience.py` — материалы, музыка, `DA_SceneLibrary`.

Генераторы перезаписывают созданные ими ресурсы, поэтому без этого ключа сборка их не трогает и
ручные правки в редакторе сохраняются.

**Паки Fab обязательны.** Сцены собраны из Wabi Sabi Boutique Guesthouse и Soul: City, а их папки
(`GratiaVR/Content/Wabi_Sabi_Interior`, `GratiaVR/Content/SoulCity`) в git не входят. На новой машине
их ставят из Epic Games Launcher по инструкции в [docs/EXPERIENCE.md](docs/EXPERIENCE.md#подготовка-контента),
затем выполняют `Build.cmd -RegenerateScenes`. Первое открытие проекта после этого компилирует
шейдеры статического освещения (около часа на этой машине).

Картинки карточек сцен берутся из кадров прошедшей проверки текущего пакета:
`Test-SceneFlow.ps1`, затем `import_scene_thumbnails.py` (коммандлет) и ещё одна сборка.

Запуск сразу в нужной сцене без лобби (замеры, длительные прогоны): `GratiaVR.exe -GratiaScene=SoulCity`
(или `WabiSabi`); настройки игрока при этом не сохраняются.

Дополнительные параметры передаются скрипту сборки или игре. Для сборки без паузы в терминале
предварительно выполнить `set GRATIA_NO_PAUSE=1`.

Логи сборки: `evidence/04/editor_build.log`, `evidence/04/package.log`. Прежние копии проекта
сохранены в `Archive/ProjectCopies`; рабочая папка одна — `GratiaVR`.
